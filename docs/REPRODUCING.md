# Reproducing the experimental stages

Run commands from the repository root. First complete the evidence-only verification in the README. Preserve `evidence/` unchanged. New experiments write to `results/`, `logs/`, `data/`, and `figures/`, which are ignored by Git. Fresh directories are included. Do not mix partial runs: some scripts intentionally reject an existing run log, while others reuse caches or resume existing metrics. Use a separate clean checkout for a new full run.

## 1 Obtain official data

CIC sources: https://www.unb.ca/cic/datasets/iotdataset-2023.html and https://www.unb.ca/cic/datasets/iomt-dataset-2024.html . IoT-23: https://www.stratosphereips.org/datasets-iot23 . Use the providers' current registration and access process. The acquisition code records the URLs used by the study; if a provider changes its form or file layout, acquisition requires review rather than substituting another dataset.

Copy `docs/cic_identity.example.json` to `tmp/cic_identity.json` and enter your own researcher registration fields. Do not commit that file. Acquisition submits those fields to the official CIC provider.

```powershell
python scripts/acquire_data.py --identity tmp/cic_identity.json --download
```

The expected source archive is `data/raw/CICIoT2023/CSV/CSV.zip`. Target files are beneath `data/raw/CICIoMT2024/WiFI_and_MQTT/attacks/CSV/`, retaining official train/test paths. The data manifest is regenerated by acquisition. Compare downloaded checksums with the released manifest before accepting a provider revision as equivalent. Registration responses and sessions remain local.

## 2 Original tabular study and tuning

```powershell
python scripts/full_study.py
python scripts/analyze_full.py
python scripts/tune_revision.py
python scripts/summarize_tuning.py
```

`full_study.py` constructs the cap-1000 cache and full deduplicated test. It scans all official files but trains on capped reservoirs. Source-only tuning and later target-validation analysis have distinct provenance; see `FULL_STUDY_PROTOCOL.md` and `TUNING_PROTOCOL.md`. The fixed seed set is 11, 23, 37, 53, and 71. Training can be lengthy; no fixed runtime or memory guarantee is asserted.

## 3 Capture splits, factorial controls, and coverage stress

```powershell
python scripts/revision_cache.py
python scripts/revision_factorial.py
python scripts/analyze_revision.py
```

This stage requires both cap-1000 and cap-5000 source caches. The factorial driver includes coverage stress and feature controls. Do not use the earlier pilot as a substitute for the full-study cohort. A pre-existing `logs/revision_factorial.jsonl` triggers a deliberate partial-run guard.

## 4 Common packet extraction and original external task

```powershell
python scripts/acquire_revision_pcaps.py
python scripts/acquire_external_extension.py
python scripts/common_pcap_features.py
python scripts/common_pcap_experiment.py
```

The registration identity from step 1 is required for CIC PCAP requests. Downloads retain declared chronological prefixes rather than complete captures. The extractor uses 100 valid packets per window and the declared connection-label coverage and unanimity filters. The eligibility extension is a disclosed pre-model label-feasibility amendment. It must precede extraction.

## 5 Conflict sensitivity and additional external captures

```powershell
python scripts/recover_conflicts.py
python scripts/conflict_sensitivity.py
python scripts/acquire_more_external.py
python scripts/extract_more_external.py
python scripts/evaluate_more_external.py
python scripts/analyze_strengthening.py
```

Conflict reconstruction depends on both source caches, the full-study pool membership, and the revision source models. Added external evaluation reuses fitted common-feature models and cutoffs; it does not fit on the added captures. All dependencies must therefore be generated by the earlier stages.

## 6 Compare with the manuscript

```powershell
python scripts/reproduce_main_results.py --root results
```

The default `--root evidence/results` summarizes the historical record. Set `--root results` only after generating the corresponding outputs. Main manuscript Table 1 uses `full/metrics.csv` at budget 100, the random/proposed methods, and target-test evaluation. Table 2 uses RF, target-validation 5% thresholds, random acquisition, and budget 250 in `revision/common_metrics.csv` and `strengthening/external_metrics.csv`. Supplement S1 Tables S1A/S1B are supported by the eligibility and conflict outputs. Native Word/PDF manuscript generation is outside this experiment repository.

Numerical agreement should be assessed with the disclosed RF floating-point tolerance and the same cohort/label-accounting rules. Do not tune a new run against the historical external outcomes and describe it as an independent validation.
